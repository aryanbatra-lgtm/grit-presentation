Key Concept

What does
"Agentic"
mean here?

A regular AI tool waits for you to give it a task and returns a result. An agentic flow is fundamentally different — it runs a loop on its own.

The factory line analogy: Think of it as a factory line with built-in QC — not a single machine. It generates, evaluates its own output, fixes problems, and only surfaces the final verified result.

Regular AI Tool

You prompt → it responds → done. Each task is independent. No memory. No self-correction. You review every output manually.

Agentic Flow

Runs a continuous loop — generates → validates → fixes → improves. Self-correcting. Memory-backed. Only final output surfaces.

The shift in human effort

From reviewing every output → to setting the rules once and trusting the loop to enforce them at scale, continuously.

Stage 1 · Deep Dive

Intelligent Generation

1

Read the curriculum skill

The agent ingests the specific learning objective from the syllabus — not a broad topic, but the exact skill to be tested.

2

Auto-generate a skill-specific prompt

No one-size-fits-all template. Each skill gets its own prompt, tuned to that concept. "Binary search termination" gets a different prompt than "React useEffect lifecycle."

3

Generate the full question package

Output per item includes: question text, correct answer, three distractors, and a full explanation — mapped to common misconceptions.

4

Ensure concept coverage

Tracks topic distribution across the batch — no concept is over-represented or skipped. Every area of the syllabus gets appropriate coverage.

Stage 2 · Deep Dive

Multi-Step Validation Engine

1

Every question enters the queue

No question skips QC. Every generated item must pass through the validation engine before it reaches a student.

2

Automated checks with reasoning

Not just pass/fail — the agent produces a written reason for every decision. If something fails, you know exactly why.

3

Multi-angle evaluation

Questions are evaluated from multiple independent dimensions simultaneously — not one generic quality score.

4

No human review per item

The system decides what's good enough. Human effort is reserved for audits and edge cases — not reviewing each question individually.

What gets validated

Factual correctness · Answer unambiguity · Syllabus alignment · Distractor plausibility · Explanation completeness · Difficulty calibration

The core "agentic" behavior

The system decides what passes without a human reviewing each item. Every rejection comes with a written reason — so nothing is a black box. Every decision is logged and traceable.

Stage 3 · Auto-Heal

Failed questions don't get discarded. They get fixed.

1

L2 fails — specific reasons extracted

Each failing sub-judge returns a concrete reason, not just "fail". E.g. "Distractor B is indistinguishable from the correct answer."

2

Only broken parts regenerated

The stem is always preserved. The system rewrites only what failed — options, answer, or explanation — based on which sub-judges rejected it.

3

Re-validated from scratch

The repaired candidate re-runs the full L1 mechanical checks and all 8 L2 AI sub-judges. No shortcuts.

4

Up to 4 attempts, escalating pressure

Each retry carries all prior failure history. If all 4 are exhausted → auto_rejected, full history preserved.

Human Role

Humans are not out of the loop.
Their role just changed.

Audit Sample

Content leads review a sample — not every question. Spot-check for edge cases and quality drift, not full approval workflows.

Test Edge Cases

Run test-case scenarios to validate that the system handles unusual or complex concepts correctly. Humans define the edge, the system handles the volume.

The L4 Label

AI picks within bounds, humans handle exceptions. L4 means the system operates autonomously within defined quality thresholds — humans step in only when those thresholds are crossed.

→ Human effort shifts from generation to verification. The cognitive work moves up the stack — from writing questions to defining quality standards.

On Risk

Every decision is logged.
Nothing is a black box.

1

Reasoning attached to every reject

The validation engine doesn't just say "fail" — it writes a reason. Every rejected question has a logged explanation of what specifically didn't pass.

2

Full traceability

If a question slips through that shouldn't have, we can trace exactly what the evaluator checked, what it saw, and why it passed. The audit trail is complete.

3

Fixable logic, not opaque models

Because every decision has reasoning, we can identify patterns in failures and fix the validation logic directly — not retrain from scratch.

4

Human audit as final safety net

Content leads run periodic audits and edge-case testing. The automation handles volume; the human handles judgement on the boundary cases.

If something goes wrong

We can trace exactly why the evaluator passed a bad question and fix the logic. It's not "retrain the AI" — it's "update the rule that was wrong."

The result

A system that fails gracefully and improves from failure. Confidence in the output comes not from trusting the AI blindly — but from the architecture of accountability built around it.
