Core Pipeline

Staged Generation — 6 Steps

Every MCQ passes through a six-stage pipeline. Each stage handles one focused task — dramatically reducing broken or inconsistent output compared to single-shot generation.

Stage 1 · AI

Stem Draft

Writes the question stem only. No options or answer at this stage. Tagged with a concept label and Bloom's taxonomy level. The format profile (stem length, preamble style, register) is injected here to steer style. Up to 2 retries on parse errors.

Stage 2 · AI

Canonical Solution

Model derives the single correct answer. All chain-of-thought working goes into a scratchpad field — the student-facing explanation must be clean prose only. A scratchpad guard retries if reasoning phrases like "let me" or "wait," leak into the explanation. A numeric consistency guard checks that numbers in the explanation agree with the keyed answer.

Stage 2b · AI

Independent Verifier

A separate model re-derives the answer from the stem alone, without seeing Stage 2's reasoning. Agreement → pipeline proceeds. Disagreement → Stage 2 retried once. If disagreement persists, it is flagged in the audit trail and the Pre-L2 Gate synthesises a fail for the arithmetic sub-judge — avoiding the cost of eight AI calls on a suspect question.

Stage 3.5 · AI

Misconception Planner

Identifies 3 primary + up to 2 alternate misconceptions specific to this question — concrete conceptual mistakes (e.g. "student applies the rule backwards"), not generic error classes. The 3 primary misconceptions seed the three distractor slots. Alternates act as reserves if a primary collision occurs in Stage 5.

Stage 4 · AI × 3 Parallel

Distractor Generation

Three AI calls run simultaneously, one per misconception. Each call produces one plausible-but-wrong option tied to that specific misunderstanding. Rules enforced: same shape and units as the correct answer, clearly wrong for a knowledgeable student, no "all of the above" patterns.

Stage 5 · Mechanical

Assembly + Collision Check

Correct option and three distractors are shuffled using a deterministic algorithm. The letter marker (A–D) is assigned by position after shuffle. Two dedup passes: exact-string match, then Dice character-bigram similarity ≥ 0.92. A collision triggers a slot regeneration using alternate misconceptions. If no alternates remain, the question is discarded.

Stage 6 · AI

Self-Critique

Model audits its own assembled question as a senior reviewer would. Re-derives the correct answer, checks that exactly one option is defensible, verifies all distractors are tied to real misconceptions, checks for ambiguous or trick phrasing, and confirms on-syllabus and correct Bloom's level.

Pass → Layer 1 Validation Fail → Targeted Retry

Every question passes through these gates in sequence. Each gate acts as a filter — questions that don't meet the bar are discarded or sent to repair before ever reaching a student.

Layer 2 · AI Judge

8 Sub-Judges in Parallel

Eight independent AI sub-judges run simultaneously, each with a separate focused prompt examining one quality dimension. A single genuine fail from any sub-judge causes the overall result to fail → Auto-Heal.

Judge 01

Syllabus Alignment

Topic is covered by the syllabus, explicitly or implicitly.

Judge 02

Unambiguity

Exactly one option is defensible; all wrong options are clearly incorrect.

Judge 03

Factual Correctness

The keyed answer is objectively correct in the subject domain.

Judge 04

Distractor Quality

Every wrong option is clearly wrong for a knowledgeable student.

Judge 05

No Trick Wording

No double negatives, confusing except/not/never constructs, or gotcha phrasing.

Judge 06

Format Match

Tone, complexity, and style match the admin's sample questions.

Judge 07

Arithmetic Accuracy

Every calculation is mathematically correct. Skipped when Stage 2b verifier already agreed.

Judge 08

Out-of-Scope Check

Doesn't require knowledge from the explicit out-of-scope list. Cross-checked vs alignment to prevent false positives.

Auto-Heal · AI

Surgical Repair — Up to 4 Attempts

Rather than discarding, the system attempts targeted repair. Specific failure reasons from all failing sub-judges are fed back as concrete repair instructions. The original stem is always preserved — only options, correct answer, and explanation are regenerated.

1

Extract all Layer 1 and Layer 2 failure criterion names with specific sub-judge rationales.

2

Include prior-attempt feedback as escalating pressure — if attempt 2 failed, attempt 3 receives both the original reasons and why attempt 2 also failed.

3

Generator returns only the corrected parts: new options, new correct answer, new explanation. Stem unchanged.

4

Healed candidate re-validated through full Layer 1 + Layer 2. Every attempt recorded on the original question's heal history.

Success

Inserted as new row with supersedesQuestionId pointing to original. Original marked superseded.

Budget Exhausted

Question auto-rejected. Full heal history preserved for audit. Concurrent admin edits are protected by optimistic concurrency.

Phase 2 + 3

Pool Generation & Live Top-Up

After calibration is approved, the system fills and maintains the question pool autonomously — no further human input required for each individual question.

⚡
Phase 2 · Automated

Full Pool Generation

Concept-targeted batches fill the pool to the size defined by the admin-approved concept plan. Pool questions are auto-approved — calibration already validated the template, so individual sign-off isn't needed.

Dedup: Cosine similarity checked against the entire existing pool on each run, not just the current batch.
🔀
Variation

Variation Generation

Creates alternate versions of approved calibration questions — same concept, different numbers, variable names, or scenario. Expands the pool efficiently without new concept work.

Admin review required: Variations are not auto-approved. Each carries a parentQuestionId lineage link.
🔄
Phase 3 · Live

Auto Top-Up

As students exhaust their unseen question inventory, the system automatically triggers background generation. New questions become available for subsequent attempts without blocking the current one.

Trigger: unseen question count drops below the configured minimum threshold.
📊
Automated

Saturation Detection

The system tracks yield rate (questions accepted ÷ questions generated) per run. Two consecutive runs below 20% yield with ≥ 50 questions in the pool → pool marked saturated and excluded from further auto top-up.

Saturation is cleared automatically if new syllabus content is added or the concept plan is updated.
